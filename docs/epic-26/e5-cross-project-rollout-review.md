## Compatibility findings

The pilots found three legacy seams before successful completion:

1. alternate-schema noise for a retained scalar short `commit_sha`;
2. lowercase `type: inbox` records using legacy `date` and missing new profile
   fields; and
3. a legacy title-only inbox index that never listed the selected files.

Each seam now has a narrow compatibility rule or bounded evidence field. Legacy
records remain warning-only inputs, genuinely malformed structures still block,
strict generated concepts remain mandatory, and duplicate linked index rows
still fail closed. These findings support warning-first, project-by-project
adoption rather than a bulk profile promotion.

The D5 source report could date only 22 of 85 records from `timestamp`. A
separate hashed exact-revision audit covered the remaining 59 legacy `date`
fields and four filename dates, leaving zero undated records and correcting the
oldest-age metric to 39 days without changing the 120-day ceiling outcome.

## Decision and reopening conditions

Broader adoption remains stopped. No cron entry, polling loop, Factory session,
automatic retry, child runtime session, network dependency, or autonomous
`AGENTS.md` mutation is active or approved. The pre-existing cron-server
LaunchAgent remains on disk for reversibility, but its launchd label is
explicitly disabled, it is unloaded, all four configured OKF curator jobs are
disabled, no server process exists, and the real crontab has zero OKF lines.
The retained disable evidence binds the exact LaunchAgent, job configuration,
and crontab hashes observed at closeout.

A later operator may reconsider the stop only through a new explicit decision
that names the project and scope. The review should then require:

1. a warning-mode audit of that project's current bundle and extensions;
2. explicit repository-local limits, selection, revision, operator identity,
   and recovery plan;
3. a time-based manual-explicit observation that can measure actual inbox
   growth, not only a frozen before/after batch;
4. the complete installer/viewer/query/hook/curator regression remaining green;
   and
5. an explicit `APPROVE`, `REVISE`, or `STOP` decision before any next project
   or stricter profile mode.

The current `STOP` leaves the accepted canonical tooling available for governed
review while preventing evidence from being stretched into rollout authority.
The live skill copies are hash-aligned; a separate scoped commit is still
required to make the dirty external distro source durable, and the pre-existing
unmanaged Factory curator copy remains outside this review's mutation authority.
